# v0.1 implementation contract

The first release is a control layer for an existing Android API 34+ emulator/device. Container boot, microVMs, custom SurfaceFlinger/HWC, iOS, and snapshot/restore are later milestones. No measured latency or speedup is promised before benchmarks.

## Guest wire protocol

Persistent TCP on guest 127.0.0.1:7777, exposed through an explicit `adb forward tcp:7777 tcp:7777`. UTF-8 newline-delimited JSON-RPC 2.0, one request/response per line, maximum 8 MiB per message. Every guest request has `token` at top level, equal to an explicit instrumentation argument; missing/incorrect tokens fail closed. No secret in checked-in files. RPC runs serially; timeout is bounded and a mutating request is never automatically replayed.

Request: `{"jsonrpc":"2.0","id":1,"token":"...","method":"ui_snapshot","params":{}}`.
Success: `{"jsonrpc":"2.0","id":1,"result":{...}}`; errors use `{code,message}`. Invalid params -32602; unknown method -32601; unauthenticated -32001; unavailable/operation failure -32000. Notifications get no response.

- `ping` -> `{version:"0.1.0", apiLevel: integer}`.
- `ui_snapshot`: `{includeInvisible?: boolean}` -> `{snapshotId: integer,nodes:[{id:integer,testId?:string,role:string,text:string,rect:[left,top,right,bottom],enabled:boolean,focused:boolean,clickable:boolean}],truncated:boolean}`. Prune empty wrappers while retaining descendants. Exclude password text. Bound traversal to 10000 nodes/128 levels; indicate truncation. Test IDs are resource IDs; Compose requires `testTagsAsResourceId=true` (extras may be best effort, never a universal claim).
- `ui_act`: `{action:"tap"|"long_press"|"type"|"clear"|"scroll_to"|"back"|"deep_link",target?:{testId?:string,text?:string,id?:integer,snapshotId?:integer},text?:string,direction?:"up"|"down"|"left"|"right"}`. Deep link URI uses `text`. Exactly one selector per target; IDs require matching snapshotId. Reject missing, ambiguous, disabled or stale target rather than choosing the first. `scroll_to` searches with bounded directional swipes until target exists or errors. Return `{snapshot: <fresh snapshot>, settled:boolean}`; quiet-window waiting is bounded, distinct from processing latency. Input uses public UiAutomation injection/AccessibilityNodeInfo actions, not hidden InputManager APIs. `type` appends; `clear` empties editable node. IME Unicode via ACTION_SET_TEXT. Scroll limit 12 swipes.
- `ui_screenshot`: `{format?:"webp"|"png",somOverlay?:boolean}` -> `{mimeType:string,data:string (base64),snapshotId:integer,marks:[{id,rect}],width:integer,height:integer}`. Public `UiAutomation.takeScreenshot`, bitmap/canvas overlay and compression; no zero-copy claim. Marks correspond to snapshot IDs; no screenshot support claims beyond tested Android API versions. Default WebP. No raw images on stdout except protocol data.
- `app_logs`: `{tagFilter?:string,sinceMs?:integer}` -> `{lines:[string],truncated:boolean}`. Guest bounded log ring from one persistent logcat reader. Filter tags literally, not shell interpolation; sinceMs is epoch milliseconds. No logs in ordinary snapshot/action responses.

## Host interfaces and ownership

Rust binary `ashnazg`: `mcp` (stdio default), `rpc METHOD [JSON_PARAMS]` (one guest RPC), `install APK [--launch PACKAGE]` (adb setup). Host env: `ASHNAZG_AGENT_ADDR` defaults 127.0.0.1:7777 and must be loopback; `ASHNAZG_TOKEN` required to start MCP or make guest calls; `ANDROID_SERIAL` selects device for adb; `ASHNAZG_ADB` optional adb executable. MCP tools: ui_snapshot, ui_act, ui_screenshot, app_logs, app_install. Advertise only implemented tools. device_boot is a later-milestone API, not a stub success. MCP screenshot emits image content. Prefer official Rust MCP SDK with stdio and Streamable HTTP (modern replacement for standalone SSE); bind HTTP loopback only and require Bearer auth. Follow negotiated supported protocol versions, never arbitrary version echo. Host never writes diagnostic logs to stdout in MCP mode. Host validates tool params and guest envelope IDs/errors; no retries on mutations.

Android Gradle root: `agent-android/`, modules `agent` and `fixture`. Java 17, compile/target SDK 35, minSdk 34, AGP 8.9.1 and Gradle 8.11.1. Agent package `dev.ashnazg.agent`; instrumentation `dev.ashnazg.agent.AgentInstrumentation` targeted at own package, started via `adb shell am instrument -w -e token "$ASHNAZG_TOKEN" dev.ashnazg.agent/dev.ashnazg.agent.AgentInstrumentation`. No test libraries required for instrumentation main; fixture launcher `dev.ashnazg.fixture/.MainActivity`. Fixture contains button resource ID `dev.ashnazg.fixture:id/increment`, text `Count: 0` -> `Count: 1`, editable resource ID `dev.ashnazg.fixture:id/input`, scrollable content, deep-link `ashnazg://fixture`. Include semantic tags/test fixture for real device tests. Agent-owned files only under agent-android/.

Harness owns scripts/, tests/ (Python standard library), .github/, Makefile; Android builds `cd agent-android && ./gradlew test lint assembleDebug`. Integration uses `python3 scripts/integration.py` and expects release/debug host `target/debug/ashnazg` or ASHNAZG_BIN, APKs in standard Gradle output paths. It manages forwarding/instrumentation/fixture installation, generated token, readiness deadline, cleanup; tests each action, stale IDs, image signatures/overlays, logs, unauthorized and malformed requests, persistent connection, and unknown tools. Scripts call adb only as project test runners, never against an unselected device. Benchmarks `python3 scripts/benchmark.py --iterations 10 --output artifacts/benchmark.json` compare persistent guest snapshots against stock adb uiautomator dump, repeated adb screencap against persistent screenshot, report cold setup separately, p50/p95, environment, raw samples and errors; fail unavailable rather than record zero. CI must run integration on real Android emulator (Ubuntu KVM) and upload evidence.
