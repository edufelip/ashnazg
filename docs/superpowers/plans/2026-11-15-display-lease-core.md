# Display Lease Core Implementation Plan

> **For agentic workers:** Use subagent-driven-development with isolated file ownership. No nested agents. Root performs specification and independent code review before integration.

**Goal:** Implement the deterministic, bounded lease policy used by the future authenticated display governor.

**Architecture:** A pure Java state machine owns renewable leases and chooses a desired rate; the Android adapter remains responsible for requesting and verifying physical modes. Inject a monotonic nanosecond clock so all expiry and quiet-grace tests run without sleeping. This component neither starts a privileged service nor claims that a display changed rate.

**Tech Stack:** Java 17 standard library, Python unittest driving a compiled Java contract harness.

- Create `tests/test_display_lease.py`.

## Fixed contract

Production constants are a 30-second lease TTL, 2-second quiet grace, and at most 16 active leases. The only constructor receives `java.util.function.LongSupplier`; production callers will pass `System::nanoTime`. Public instance methods are synchronized so clock reads and policy updates have one ordering. All operations are bounded by the 16-entry map.

The intended API is:

```java
public LeasePolicy(LongSupplier clock);
public boolean acquire(String leaseId);
public boolean renew(String leaseId, long sequence);
public boolean release(String leaseId);
public int desiredHz();
public int activeCount();
public long nanosUntilNextChange();
public long remainingNanos(String leaseId);
```

Lease IDs are canonical lowercase UUID strings, generated by the authenticated caller or protocol layer. Invalid IDs throw `IllegalArgumentException`. The core never logs IDs, credentials, UI data, or package information. Authentication and peer identity must be checked before invoking it.

- At construction the desired rate is 60 Hz for one quiet grace, then 1 Hz if no lease arrives.
- `acquire` removes expired leases, then creates a lease expiring at the current monotonic time plus TTL. It returns true for a new lease. Retrying an active ID returns false without extending its expiry or resetting its renewal sequence. A seventeenth distinct active lease throws `IllegalStateException` without changing existing deadlines.
- `renew` requires a positive sequence equal to the previous sequence plus one; the first is 1. A valid renewal extends that lease to current time plus TTL. Missing, expired, stale, repeated, skipped, or exhausted sequences return false and cannot revive a lease. Reject nonpositive sequences as invalid arguments.
- `release` removes an active lease and returns true; absent or expired IDs return false. Releasing the last active lease starts the fixed quiet grace. Repeated release cannot extend grace.
- Expiry uses the original expiry deadline, not the time a later observer notices it. When the last outstanding lease expires, quiet grace ends at the last expiry plus two seconds. Polling never moves that deadline.
- Any active lease keeps the desired rate at 60 Hz. With no active lease, the rate is 60 Hz until quiet grace ends and 1 Hz afterward. A new lease during grace cancels the idle transition.
- `nanosUntilNextChange` returns the time until the next active-lease expiry, or the remaining quiet grace when no lease exists; it returns zero for settled idle. `remainingNanos` returns zero for an absent/expired lease and never reports a negative duration.
- Use subtraction-based deadline comparisons compatible with `System.nanoTime` wraparound. Do not interpret its absolute value as a wall-clock timestamp. The production durations are fixed and far below half the signed-long range.
- Physical readback failure cannot be represented as successful mode control by this class. The eventual service must fail acquisition before UI work unless its adapter verifies 60 Hz. Policy decisions alone are insufficient proof.

## Task 1: Contract tests first

- [ ] Write a Python unittest that compiles the real class and a Java harness into a temporary directory using the installed JDK; skip only when javac/java are unavailable.
- [ ] Use `AtomicLong` as the injected clock and UUID constants as IDs. Exercise startup grace, acquisition, duplicate acquisition without TTL extension, exact renewal ordering, last release, repeated release, expiry, late observation without sliding grace, overlapping leases, capacity refusal, invalid IDs, absent remaining duration, and nanosecond wraparound. Include a concurrent acquire/release case proving the bounded map remains consistent.
- [ ] Run `python3 -m unittest tests.test_display_lease -v` before implementation and retain the expected failure. The first failing assertion or compilation must identify the missing core rather than an unrelated dependency.

Representative timing assertions (with `SECOND = 1_000_000_000L`) are:

```java
AtomicLong now = new AtomicLong(0);
LeasePolicy policy = new LeasePolicy(now::get);
assertEquals(60, policy.desiredHz());
now.set(2 * SECOND);
assertEquals(1, policy.desiredHz());
assertTrue(policy.acquire("00000000-0000-0000-0000-000000000001"));
now.set(31 * SECOND);
assertEquals(60, policy.desiredHz());
now.set(34 * SECOND);
assertEquals(1, policy.desiredHz());
```

The lease created at second 2 expires at second 32; its quiet grace ends at second 34. Observing it for the first time at second 100 must return idle immediately rather than starting a new grace at 100.
